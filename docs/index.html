Sveet

The opinionated agent-first SvelteKit starter kit, sweet as candy 🍬

SvelteKit + SQLite, a sandbox your agents can't escape. Skills instead of plugins. Built from years of experience in building software, and hands-on experience in shipping products with Agents. Sveet is powering onelink.ninja and more in production, and all learnings flows back here.

Why another starter?

A few things that make starting easier. Not every feature you might need.

Most starters ship so much that you spend the first week deleting. Sveet ships one stack and one way to do each thing, and lets your agents add exactly what your project needs, without dead code.

🏝️

Self-reliant

SvelteKit + SQLite and a little glue. One compiled executable, no database server, no selling your soul to a big host. Fly.io is the easy default; it's plain Docker, so it runs anywhere.

🤖

Agent-first

No pile of docs, no plugin system. Your agents get a sharp AGENTS.md, the Svelte MCP and project skills that set up, extend, deploy and upgrade the app for you.

🛡️

Sandboxed

Agents run in a small Linux VM with your project folder and the internet, and nothing else. Your SSH keys and credentials stay safe. Deploys stay on your machine.

🍬

Defaults, not handcuffs. Picks like Scaleway and Fly.io are opinionated, sensible defaults so you can ship on day one. Want Resend, Postmark, Railway or your own box? Eject and swap them: the sveet-mail and sveet-deploy skills walk your agent through it.

Getting started

Three steps. The agent does the rest.

💡

Heads-up: the sandbox is optional. It needs an Apple Silicon Mac or Linux with KVM. Elsewhere, skip it and run everything with bun on your machine: bun install && bun run setup && bun run dev. Your agent then has your user's full access, so keep its permission prompts on.

Install the tools

bun, microsandbox for the dev VM, and flyctl if you want to deploy. Or grab the Brewfile. 

$ brew install bun \
  superradcompany/tap/microsandbox \
  flyctl

Create & boot

The first boot takes a few minutes. After that, about a second.

$ bun create nerdwerk/sveet my-app
$ cd my-app && bun run sandbox
  App    http://localhost:5173
  Agent  http://localhost:4096

Say “set this project up”

The sveet-setup skill asks for a name, a one-liner, deploy and mail. “Just the defaults” and you're done after two questions. It rewrites the project and runs the tests.

Prefer the Svelte CLI?

Sveet is also an sv community add-on and produces the exact same project. 

$ npx sv create my-app --template minimal --types ts --add @nerdwerk --install bun
Working in the sandbox

Let agents go wild. Just not on your machine.

The agent runs without permission prompts, but it only sees your project folder and the public internet. The folder is mounted live, so your editor sees every change. And bun run deploy refuses to run in the VM, so nothing ships to production by accident.

Bring your agent: opencode (default, web UI on :4096), Claude Code or Codex. Or drive the VM's agent from Zed over ACP.

How agents write code here

Skills instead of plugins. Less code instead of more.

ponytail makes agents use what's already there before writing anything new. Every feature gets an e2e test of its happy path, and done means bun run verify passed. Project skills teach the flows:

  • sveet-setup

    Interviews you, then turns a fresh checkout into your own named, configured project.

  • sveet-feature

    The build loop for every feature: spec, schema, server logic, UI, tests, verify.

  • sveet-deploy

    Ships to Fly.io and handles secrets, domains, rollbacks and production backups.

  • sveet-mail

    Swaps in your mail provider of choice and adds new kinds of mail.

  • sveet-admin

    Adds health checks, shell-only superusers and a minimal admin dashboard.

  • sveet-upgrade

    Pulls improvements from newer Sveet releases in without losing your own changes.

  • ponytail

    Makes agents write the smallest change that fully solves the task.

  • ui-sdk

    Teaches agents to build accessible interfaces from ui-sdk components.

🔁

You own every line

A Sveet project is a copy, not a dependency. Say “upgrade sveet” and the sveet-upgrade skill diffs your release against the newest and applies what fits.

🚀

Ship in four commands

Create the Fly app, a volume, set the secrets, bun run deploy. The image is one executable plus migrations on debian-slim. No bun, no node_modules at runtime.

✅

One gate everywhere

Lint, types, unit and e2e on the production build. The same verify runs in the pre-push hook, in CI and before every deploy.

Is it for you?

Probably. Unless…

🍭 Sweet fit

  • You want a kickstart, not a kitchen sink
  • You want to ship a real product fast, with agents doing the typing
  • One server and SQLite go a long way for you
  • You like owning your stack and your data
  • You're on macOS or Linux

🙅 Not your candy

  • You want to start inside a specific ecosystem like Supabase, Firebase or Convex
  • You want lots of boilerplate done for you: billing, teams, dashboards
  • You need Postgres or multiple servers from day one
  • You don't want to work with agents
